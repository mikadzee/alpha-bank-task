# Alfa Bank — умный кредитный кабинет

Демонстрационный MVP кредитного конвейера для малого бизнеса. В одном веб-приложении работают кабинет клиента и закрытое рабочее место банковского сотрудника. Проект запускается через Docker Compose; отдельная установка Python/Node на хосте не нужна.

## Быстрый запуск

Нужны Docker Desktop и команда `docker compose` (Compose v2). В корне репозитория:

```bash
cp .env.example .env
docker compose up --build
```

Адреса после старта:

- Кабинет: http://localhost:3000
- API: http://localhost:8000
- Swagger: http://localhost:8000/docs
- OpenAPI JSON: http://localhost:8000/openapi.json
- Health check: http://localhost:8000/healthz

Проверка состояния API без браузера: `curl http://localhost:8000/healthz`.

## Демо-входы

При `ENABLE_DEMO_ACCOUNTS=true` API создаёт локальные учётные записи. Пароли существующих пользователей не сбрасываются.

| Роль | Email | Пароль |
|---|---|---|
| Клиент-предприниматель | `demo@creditory.local` | `ClientDemo2026!` |
| Сотрудник банка | `reviewer@creditory.local` | `ReviewerDemo2026!` |

Клиенту доступно создание нескольких заявок и компаний. Публичная регистрация создаёт только роль `client`; роль `employee` назначается только конфигурацией демо-пользователя.

Полный сценарий для показа клиентского пути, уточнения, решения банка и повторной отправки описан в [docs/demo-guide.md](docs/demo-guide.md). ## Возможности MVP

- Регистрация, вход, выход и обновление сессии через ротацию refresh token в HttpOnly cookie.
- Несколько компаний на аккаунт и несколько заявок; черновики сохраняются и остаются в истории.
- Поиск по локальному синтетическому справочнику ИНН.
- Демо-каталог кредитных продуктов, аннуитетный расчёт, анализ денежного потока и детерминированные пояснения на основе введённых данных и правил продукта. Внешние ИИ-сервисы не используются.
- Проверка обязательных документов при отправке, загрузка PDF/JPEG/PNG до 10 МБ и скачивание владельцем/сотрудником.
- Отдельная очередь сотрудника с поиском, просмотром заявки, документов и прозрачной предварительной оценкой.
- Решения банка: одобрение, запрос уточнений, отказ или встречное предложение суммы/срока; клиент может исправить и повторно отправить заявку после запроса, принять или отклонить встречные условия.
- История ключевых событий заявки для клиента и сотрудника.
- Каталог продуктов, список компаний и документов, история заявок и персональная демонстрационная лента.

## Ограничения и логика рекомендаций

Сумма предложения, ставка, срок и ежемесячный платёж рассчитываются на backend по параметрам активного демонстрационного продукта и формуле аннуитетного платежа. Варианты сортируются по соответствию указанной цели, покрытию платежа денежным потоком, ставке и размеру платежа. Пояснения формируются детерминированными правилами из тех же данных; они не являются генерацией текста, банковским скорингом или решением о выдаче кредита. Решение по заявке фиксирует сотрудник в рабочем месте банка.

Справочник компаний/ИНН, кредитные продукты и отраслевые подсказки синтетические. Внешние системы ФНС, БКИ и Альфа-Банка не подключены. Ставки и суммы не являются офертой, одобрением или обещанием выдачи кредита. Демо-документы нельзя выдавать за документы реальных компаний.

## Настройки

Скопируйте `.env.example` в `.env`. Основные параметры:

| Переменная | Для чего |
|---|---|
| `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Локальная база PostgreSQL |
| `JWT_SECRET_KEY` | Подпись access/refresh токенов; замените перед публикацией |
| `NUXT_PUBLIC_API_BASE` | URL API, доступный браузеру |
| `REFRESH_COOKIE_SECURE` | `true` для HTTPS, `false` только для локального HTTP |
| `ENABLE_DEMO_ACCOUNTS` | Создание демонстрационных аккаунтов; выключить при публичном размещении |
| `DEMO_CLIENT_EMAIL`, `DEMO_CLIENT_PASSWORD` | Локальный аккаунт клиента |
| `DEMO_EMPLOYEE_EMAIL`, `DEMO_EMPLOYEE_PASSWORD` | Локальный аккаунт сотрудника |
Файл `.env` не добавляйте в Git. Для внешнего демо замените локальные секреты, выключите предсказуемые демо-аккаунты, включите Secure cookie, задайте точный HTTPS origin и используйте управляемую базу/хранилище. Текущий Compose предназначен для локального запуска, а не для публичного production-размещения.

## Остановка и данные

`Ctrl+C`, затем `docker compose down` остановит сервисы, сохранив базу и файлы в Docker volumes. `docker compose down -v` удалит их вместе с заявками и аккаунтами.
