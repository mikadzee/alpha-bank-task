# Сценарии проверки MVP

Сценарии рассчитаны на локальный запуск через Docker Compose и синтетические данные. Их можно пройти через веб-интерфейс; соответствующие API-запросы собраны в `alpha-bank.postman_collection.json`. Решение не вызывает внешние ИИ-сервисы, ФНС, БКИ или системы Альфа-Банка.

| № | Сценарий | Проверяемые действия | Ожидаемый результат |
|---|---|---|---|
| 1 | Регистрация и сессия клиента | Зарегистрировать клиента, обновить страницу, выйти и войти повторно | Регистрация создаёт роль `client`; refresh обновляет сессию; после повторного входа открывается кабинет |
| 2 | Несколько профилей и заявок | Создать два профиля компании и два черновика; открыть список компаний и заявок | Оба профиля и обе заявки отображаются; сохранённые данные черновика восстанавливаются после повторного входа |
| 3 | Изоляция аккаунтов и ролей | Клиент пытается открыть банковскую очередь; другой клиент запрашивает заявку по чужому ID | API отклоняет доступ: сотрудник банка нужен для маршрутов `/staff`; чужая заявка недоступна владельцу другого аккаунта |
| 4 | Проверка ИНН | Найти ИНН из локального справочника, затем неизвестный ИНН | Для тестового ИНН возвращаются синтетические реквизиты; неизвестный ИНН можно заполнить вручную |
| 5 | Подбор предложений | Заполнить финансовые данные и запросить рекомендации для разных сумм, сроков и целей | Backend возвращает активные продукты, аннуитетный платёж и объяснения по введённым цифрам; сетевой ИИ-вызов не выполняется |
| 6 | Валидация документов | Загрузить обязательные PDF; попробовать отправить без обязательного типа или с неподдерживаемым содержимым | Допустимые файлы принимаются; неполный комплект не отправляется; неверный тип или сигнатура файла отклоняются |
| 7 | Подача заявки | Выбрать продукт и отправить заполненную заявку с обязательными документами | Статус становится `pending`; повторная отправка той же заявки не создаёт второй объект |
| 8 | Рассмотрение сотрудником | Войти демо-сотрудником, найти заявку, открыть данные и документы, одобрить её | Заявка появляется в очереди; действие сотрудника меняет статус; клиент видит решение и событие в истории |
| 9 | Запрос уточнения и повторная отправка | Сотрудник выбирает `needs_info` и указывает комментарий; клиент исправляет заявку и отправляет её снова | Комментарий виден клиенту; исправления сохраняются; статус возвращается в `pending`, история сохраняет оба этапа |
| 10 | Отказ и встречные условия | Сотрудник отклоняет заявку с комментарием либо предлагает допустимые сумму/срок; клиент принимает или отклоняет предложение | Статусы и комментарии отображаются обеим сторонам; платёж встречного предложения пересчитывается сервером; действие клиента записывается в историю |
| 11 | Перезапуск и хранение | Остановить Compose без `-v`, запустить снова | PostgreSQL сохраняет учётные записи, заявки, события и профили; Docker volume сохраняет документы |

Для локальной проверки используйте тестовые аккаунты и документы из `docs/demo-guide.md`. `docker compose down -v` очищает данные и не должен применяться до завершения демонстрации.
